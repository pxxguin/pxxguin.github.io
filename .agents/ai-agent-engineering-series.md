## 시리즈 공통 방향

시리즈 전체 제목은 다음을 기본값으로 사용한다.

> AI 에이전트 엔지니어링: 데모를 넘어 운영 가능한 시스템 만들기

24편 모두 온라인 쇼핑몰의 **주문·환불 처리 에이전트**를 공통 사례로 사용한다. 각 글에서는 앞 글의 결과를 짧게 복습하고 기능을 하나씩 확장한다.

```text
사용자 요청
  → 의도 파악
  → 주문 조회 도구 호출
  → 환불 조건 판단
  → 필요하면 사람에게 승인 요청
  → 결과 응답
  → 실행 기록과 평가 데이터 저장
```

책을 순서대로 요약하지 않는다. 각 포스팅은 독자의 질문 하나를 출발점으로 삼아 독립적인 문제 해결 글로 재구성한다.

## 포스팅 사이의 경계

인접한 글에서 같은 내용을 반복하지 않도록 다음 경계를 지킨다.

- 2편은 핵심 구성요소의 전체 설계를, 3편은 단일·멀티 아키텍처 선택과 트레이드오프를 다룬다.
- 4편은 입력·출력 양식별 인터페이스를, 5편은 자율적 행동을 사용자가 통제하는 경험을 다룬다.
- 6편은 외부 기능 연결 방식과 MCP를, 7편은 도구의 입력·출력 계약과 오류 설계를 다룬다.
- 8편은 다음 행동을 선택하는 추론 패턴을, 9편은 선택된 행동의 실행 순서와 상태 관리를 다룬다.
- 10편은 벡터 검색과 일반 RAG까지, 11편은 관계 중심 검색과 GraphRAG를 다룬다.
- 12편은 모델 가중치를 바꾸지 않는 학습을, 13편은 가중치를 바꾸는 학습을 다룬다.
- 14편은 에이전트 수를 정하고, 15편은 결정권과 조직 구조를 정하며, 16편은 통신과 상태 보존을 구현한다.
- 17편은 도구·계획·메모리 등의 단위 평가를, 18편은 엔드투엔드 평가와 배포 판단을 다룬다.
- 20편은 실패를 수정 후보로 만드는 과정을, 21편은 수정안을 실험하고 학습에 반영하는 과정을 다룬다.
- 22편은 공격 표면과 위협 모델을, 23편은 실제 방어 계층과 권한 통제를 다룬다.

## 개별 포스팅 작성 절차

1. 이 문서에서 포스팅 번호, 책 페이지, PDF 페이지를 확인한다.
2. PDF의 담당 범위와 앞뒤 1쪽을 읽는다. 앞뒤 1쪽은 문맥 확인에만 사용한다.
3. 같은 시리즈의 직전 포스팅을 읽고 이미 설명한 부분과 다음 글 예고를 확인한다.
4. 담당 글의 핵심 질문에 답하는 목차를 먼저 만든다.
5. 변경 가능성이 있는 프로토콜, 라이브러리, 모델, API 정보는 최신 공식 문서로 검증한다.
6. 실습 코드와 명령을 실제로 검증하고 정상·실패 결과를 함께 해석한다.
7. 저장소 루트 `AGENTS.md`의 블로그 문체, 강조 문법, 코드 블록 규칙을 적용한다.

## 완료 조건

- 배정받은 페이지의 핵심 절을 빠짐없이 반영했다.
- 앞뒤 포스팅과 내용이 크게 중복되지 않는다.
- 핵심 질문에 대한 작성자의 판단이 결론에 남아 있다.
- 책의 분류를 단순 번역·나열하지 않고 쉬운 사례로 다시 해석했다.
- 코드, 명령, 예상 출력과 설명이 서로 일치한다.
- 정상 경로뿐 아니라 장애, 중복, 권한, 유실 등 경계 조건을 다뤘다.
- 기술을 사용하지 않아도 되는 조건과 운영 비용을 함께 설명했다.
- 변경 가능한 사실은 최신 공식 문서나 1차 출처로 검증했다.
- 책의 문장을 과도하게 인용하거나 재현하지 않았다.
- 저장소의 Markdown 강조 문법과 코드 블록 규칙을 지켰다.
